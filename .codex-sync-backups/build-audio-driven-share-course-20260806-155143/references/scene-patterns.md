# Semantic scene patterns

Choose one dominant pattern per scene. Combine only when the narration clearly changes mode inside the scene.

| Meaning in narration | Useful stage pattern | Cue progression |
|---|---|---|
| Definition or new role | Term assembly | Old labels appear → recede → new term assembles → outcome path connects |
| Real-world obstacles | Layered constraint stack | Abstract metrics fade → concrete constraints accumulate → root issue focuses |
| Simple request hiding complexity | Expanding case map | Simple UI appears → rules branch → workflow and monitoring layers open |
| Hybrid responsibilities | Role merge | Two roles enter from opposite sides → merge → capabilities light up |
| Hidden system chain | Hub and dependency path | User action appears → edge cases orbit → request/database/log chain grows |
| Uncertainty or risk | Stable flow disrupted | Normal flow connects → uncertain states interrupt → ownership question appears |
| Capability gap | Before/after divide | Old evidence and new evidence separate → empty-project gap appears → candidates emerge |
| Full delivery lifecycle | Horizontal or vertical pipeline | User → problem → interface → data → permissions → deployment → feedback |
| AI plus human ownership | Generated layer with review overlay | AI produces artifacts → human layer checks → security details unfold → delivery chain seals |
| Evidence hierarchy | Three proof layers | Files fade → usable product appears → explanation and retrospective archive |
| Resume or portfolio | Document generation | Weak tool names recede → specific project line types in → responsibilities and proof settle |
| Value transformation | Paired conversions | Old metric → judgment → system outcome → final delivery |
| Action close | Connected implementation loop | Site → database → domain → deployment → users → feedback → responsibility statement |

Avoid generic floating cards when a process, contrast, or dependency is the actual point.
