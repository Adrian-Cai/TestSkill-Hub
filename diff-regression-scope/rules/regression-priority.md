# 回归优先级判定规则

## 必测

满足任一条件时列为必测：

- Diff 直接修改的核心业务流程
- 影响支付、订单、退款、库存、权限、登录、数据一致性
- 新增或改变状态流转、参数校验、错误码、接口返回结构
- 线上高频入口或历史高发缺陷区域
- 一旦出错会阻断主流程、造成资金或数据风险

输出时必须写清“必测原因”。

## 建议测

满足任一条件时列为建议测：

- 间接受影响的上下游链路
- 依赖变更模块输出的功能
- 低频但业务重要的边界流程
- 现有自动化可能被返回字段、错误码、状态变化影响
- 历史缺陷相关但本次 Diff 未直接修改

## 可抽测

满足任一条件时列为可抽测：

- 展示类、查询类、低频后台功能
- 与变更点弱相关，但共享同一数据或状态
- 影响后果较轻，且有自动化或监控兜底

## 可暂不测

只有在理由充分时才列出：

- 与 Diff 无调用关系、无共享数据、无共同配置
- 仅纯文案、注释、无行为变化的改动
- 已有稳定自动化覆盖且本次未改变断言相关行为

可暂不测必须说明理由，不能作为缩减测试范围的借口。

## 风险等级

- 高：主流程、资金、权限、数据一致性、强依赖下游
- 中：重要分支、兼容性、异常路径、历史缺陷区域
- 低：低频展示、弱依赖、可通过抽测确认
