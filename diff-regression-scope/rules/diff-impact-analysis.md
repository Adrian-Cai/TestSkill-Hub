# Diff 影响面分析规则

## 先看事实层

从 Diff 中提取：

- 改动文件、模块、函数、类、接口
- 新增、修改、删除、重构、配置调整
- 参数校验、状态流转、异常处理、返回字段、数据字段、权限逻辑
- 测试文件是否同步修改，以及是否存在明显遗漏

## 再推直接影响

直接影响通常包括：

- 被修改接口本身
- 被修改函数或服务承载的业务动作
- 被修改状态、字段、配置直接参与的页面或流程
- 新增校验、异常码、返回字段直接影响的调用方

## 再推间接影响

间接影响重点看：

- 上游：哪些入口会触发被改逻辑
- 下游：被改逻辑会调用哪些外部模块或服务
- 共享：公共方法、工具类、组件、配置被谁复用
- 数据：历史数据、空值、默认值、枚举值是否兼容
- 自动化：现有用例、Mock、断言是否因返回结构或状态变化失效

## 常见高风险 Diff 类型

- 订单、支付、退款、库存、权限、登录、结算等核心链路
- 状态机变化，例如新增状态、改变流转条件、改变重复操作行为
- 参数从可选变必填，或校验规则变严
- 接口返回字段、错误码、HTTP 状态码变化
- 数据库字段、枚举值、默认值变化
- 异步任务、消息队列、回调、定时任务变化
- 公共方法或共享组件变化

## 输出要求

影响面不能只写模块名称，必须说明：

- 为什么这个模块受影响
- 影响来自哪一类代码变化
- 是否需要进入必测 / 建议测 / 可抽测
- 是否需要人工确认真实调用关系
