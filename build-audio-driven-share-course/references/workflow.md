# 标准工作流

## 阶段 A：确认素材

- 确认用户指定的音频文件。
- 检查扩展名与真实容器是否一致。
- 记录容器时长、解码时长、第一帧时间戳、正文开始位置。
- 判断文件是完整录音、分段录音还是重新导出的片段。

## 阶段 B：建立文本基准

- 有本地 ASR：直接转写当前音频。
- 有完整课程转写：先做文本区间定位，再做时间重映射。
- 只有人工稿：将其视为文字底稿，不伪造单词级置信度。

## 阶段 C：场景规划

每段旁白先回答三件事：

1. 这一段改变了观众的哪个认识？
2. 哪种视觉关系最能承载这个变化？
3. 画面中必须保留的最短文案是什么？

再把每段拆成语义 cue：每个 cue 只保留一个主信息，最多一个辅助图形；上一 cue 在下一 cue 出现时退场。不建立用于自动补位的全局标题、场景标题、摘要或章节字段；需要呈现的标题式判断也必须写成普通 cue。

## 阶段 D：编码

- 默认单文件 HTML。
- CSS 负责布局和基础过渡。
- SVG 负责连线、流程和关系表达。
- JavaScript 根据 `audio.currentTime` 重建状态。
- 没有当前 cue 时保持录制舞台空白，不得回退显示项目名或场景名。
- 不以 `setTimeout` 作为主时间轴，因为拖动和重播会失效。
- 预览控制放在 1920×1080 舞台之外；录制舞台默认不含课程包装、时钟、章节栏、cue 标签或进度条。

## 阶段 E：录制

- 本地启动 HTTP 服务。
- OBS 添加浏览器来源。
- 使用 `record=1&autoplay=1&delay=3`。
- 后期在剪映中裁切或重构成 9:16。
