# 场景设计规则

## 默认录制画布

录制画布只承载旁白对应的正文与必要图形。默认不要在 `1920 × 1080` 舞台内放置：

- 品牌、课程名称或栏目包装
- 时钟、章节列表或章节进度点
- cue 动作名、调试提示或重复字幕
- 播放进度条、按钮或录制状态

预览控制放在舞台外。只有用户明确要求时，才把上述元素作为视觉内容加入画面。

## 单拍呈现契约

每个 cue 是一个 beat。任意时刻默认满足：

1. 只有当前 beat 可见。
2. 当前 beat 只有一个主信息，最多搭配一个辅助图形。
3. 上一 beat 退场，不以降低透明度或“已完成”状态继续驻留。
4. 下一 beat 保持不可见。
5. 拖动时间轴后，直接由 `audio.currentTime` 重建当前状态。

推荐结构：

```html
<section class="panel" data-scene="scene-id">
  <div class="beat" data-step="0">...</div>
  <div class="beat" data-step="1">...</div>
</section>
```

```css
.beat{opacity:0;transform:translateY(24px) scale(.985);pointer-events:none}
.beat.is-current{opacity:1;transform:none;pointer-events:auto}
.beat.is-past{opacity:0;transform:translateY(-20px) scale(.99)}
```

不要只切换高亮色而让所有 cue 元素持续可见。

## 视觉结构选择

| 旁白关系 | 推荐结构 |
|---|---|
| 两种观点冲突 | 单拍左右对照，下一拍切到结论 |
| 输入经过处理得到输出 | 单条横向流水线 |
| 表面成功但实际错位 | 完成状态与错位标准框分拍展示 |
| 一个概念包含多层规则 | 外壳打开后逐层替换，不同时堆满 |
| 两类工具本质不同 | 稳定分屏对照 |
| 同一任务有不同标准 | 单输入逐拍切换不同结果 |
| 隐藏前提导致失败 | 每拍只展示一个缺失条件或错误 |

## 文案规则

- 音频承担完整解释，屏幕只保留判断和关系。
- 同屏核心文案不超过两个层级。
- 不展示整段逐字稿，不重复底部字幕。
- 不添加旁白没有支持的预告、指标或结论。
- 不配置会被自动回退渲染的全局标题、场景标题、眉题或摘要。旁白确实需要标题式判断时，将它写成普通 cue，作为一个 beat 出现后退场。

## 转场规则

转场复用上一个场景的视觉对象或方向，例如：

- 输入卡片沿同一方向进入下一段流水线。
- 上一拍的输出文件成为下一拍的对比对象。
- 结论关键词缩小后转化为下一场景的节点。

转场仍需遵守单拍呈现契约，不应在过渡后留下旧内容。
