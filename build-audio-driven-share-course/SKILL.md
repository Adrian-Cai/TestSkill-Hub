# 音频驱动分享课程制作器

当用户提供旁白音频，希望制作同步动画课程、技术讲解或可通过 OBS 录制的网页场景时，使用本 Skill。

## 核心原则

音频是唯一事实来源。在检查并对齐当前音频之前，不要根据旧转写、文件名或假定的一分钟结构设计场景。

## 默认制作标准

- 录制页面：桌面横屏，`1920 × 1080`。
- 录制方式：使用 OBS Browser Source，不录制 Chrome 窗口。
- 最终竖屏交付：录制后在剪映或 CapCut 中裁切或重构。
- 字体排版：使用适合演示的大字号，但不要制作成手机页面布局。
- 录制画布：默认只保留内容。除非用户明确要求，不要在 `1920 × 1080` 舞台内放置 Logo、课程名称、时钟、章节栏、cue/action 标签、重复字幕或进度条。
- 预览控制：播放、拖动、状态和调试界面必须放在录制舞台之外；`record=1` 时只能留下旁白驱动的内容。
- cue 可见性：同一时间只展示一个主信息 beat，最多搭配一个辅助图形。上一 beat 必须退场，不能以变暗或“已完成”状态继续驻留。
- 交付内容：提供一个嵌入音频的独立 HTML 预览、转写 JSON、时间轴 JSON、README、启动脚本和 ZIP。
- 运行方式：优先使用无依赖的 HTML、CSS、JavaScript 和 SVG。仅当项目已有可用的本地工具链，或交互确实需要时，才使用 React 或 GSAP。

## 必要输入

至少需要：

1. 一个音频文件。
2. 一个主题或对应部分名称。

可选但有帮助的输入：

- 完整录音的主转写稿。
- 主时间轴。
- 之前的场景样式或项目文件夹。
- 用户提供的技术术语修正。
- 目标场景边界或章节范围。

## 强制工作流

### 1. 检查实际音频

运行：

```bash
python scripts/inspect_audio.py "<audio-path>" --output audio-report.json
```

检查：

- 容器格式和实际编码；文件扩展名可能具有误导性。
- 容器显示时长。
- 解码后的音频时长。
- 第一帧音频时间戳。
- 开头是否存在时间戳空白或静音。
- 文件是新录音、原录音节选，还是重新导出的片段。

不要仅因为两个文件听起来相似，就推断它们共用同一条时间轴。

### 2. 转写或对齐

按以下优先顺序处理：

1. 使用可用的 ASR 引擎直接转写用户提供的音频。
2. 如果音频是已验证完整录音的节选，在主转写中定位准确文本区间，并与节选音频对齐。
3. 如果无法直接使用 ASR，只有在核对首句、尾句、内容顺序和时长后，才使用已有转写。

将原始 ASR 结果保存在 `transcript.raw(<part>).json`。编辑修正应写入展示用时间轴标签或单独的清洗稿，不要修改原始置信度，让修正内容看起来像 ASR 的原始输出。

技术术语修正示例：

- `secure`、`sec ure` → `Skill`
- `talking` → `Token`
- `测试用力` → `测试用例`
- `报款文章` → `爆款文章`
- `评论器` → `评论区`

只修正能够被上下文支持的术语。

### 3. 必要时使用锚点重映射时间

创建锚点文件：

```json
{
  "anchors": [
    {"source": 0.0, "target": 10.46},
    {"source": 100.02, "target": 109.72}
  ]
}
```

然后运行：

```bash
python scripts/retime_json.py \
  --input-transcript master-transcript.json \
  --input-timeline master-timeline.json \
  --anchors anchors.json \
  --output-dir aligned
```

至少使用两个已经核实的锚点。如果音频存在剪辑、停顿或局部速度变化，应增加锚点。局部时间可能不一致时，不要使用简单的全局时长比例缩放。

### 4. 定义语义场景

不要强制每分钟一个场景。只有当论点、认知模型、示例或视觉语法发生变化时才切换场景。

每个场景需要定义：

- 叙事任务。
- 开始和结束时间。
- 一个主导视觉隐喻。
- 4–10 个有意义的 cue。
- 只有当旁白确实完成论证时，才设置最终结论。

使用 `examples/scene-plan.example.md` 作为规划格式。

### 5. 建立时间轴

使用以下结构：

```json
{
  "duration": 111.307,
  "source": "audio/part.m4a",
  "contentStart": 10.46,
  "scenes": [
    {
      "id": "01",
      "start": 10.46,
      "end": 111.307,
      "layout": "opening-to-mismatch",
      "cues": [
        {
          "at": 10.46,
          "action": "reveal",
          "target": "debate",
          "label": "Skill 到底有没有用"
        }
      ]
    }
  ]
}
```

每个 cue 必须位于所属场景的时间范围内。场景之间不能重叠。

### 6. 设计动画

遵循“一个语义 cue，一个聚焦 beat”，不要为旁白中的每一句话都制作一段动画。

默认 cue 行为：

1. 使用 `opacity` 和 `transform` 让当前 beat 进场。
2. 当前 beat 出现时立即让上一 beat 退场；不要仅降低透明度后继续保留。
3. 同屏只保留一个主文案块，最多一个辅助图形。
4. 不要建立会被自动渲染的全局标题、场景标题、眉题或摘要字段。旁白确实需要呈现标题式判断时，把它写成普通 cue，并按一个 beat 展示后退场。
5. 根据 `audio.currentTime` 重建准确的当前 beat，保证拖动后不会遗留旧元素。

推荐视觉形式：

- 争论或矛盾：对立卡片、汇聚线条、中心冲突标记。
- 流程：流水线、节点、进度状态、文件夹、输出检查。
- 概念揭示：外壳打开、图层分离、标签出现。
- 对比：稳定分屏、左右同步路径。
- 错位：完整输出与用户标准框叠加但无法对齐。
- 隐藏前提：外壳中展开语言、目录、格式和工具依赖。
- 失败：终端或环境面板，展示旁白明确支持的错误。

避免：

- 同时展示多个文案块、卡片和图表。
- 只改变当前项高亮颜色，但让其他所有内容继续留在画面中。
- 在录制画布中永久显示品牌或课程名称、时钟、章节列表、进度条、action 标签、调试字幕或重复字幕。
- 为语气词或每一句话都创建新 beat；同一语义观点的相邻旁白应合并。
- 不能表达含义的装饰粒子。
- 密集的段落字幕。
- 竖屏重构后无法阅读的小字号界面文字。
- 旁白没有提到的指标或虚假准确率。
- 在桌面 OBS 录制页面中使用手机应用布局。

### 7. 字体与安全构图

对于 `1920 × 1080` 录制画布：

- 主信息：约 `72–104 px`。
- 核心结论：约 `64–96 px`。
- 卡片标题：约 `38–56 px`。
- 辅助文字：约 `22–32 px`。

将核心信息放在画面中央附近，便于在剪映或 CapCut 中裁切为 `9:16`，但不要把整个页面强制压缩到狭窄的手机列中。`?guide=1` 只用于显示裁切参考线。

### 8. 创建项目外壳

运行：

```bash
python scripts/create_project.py \
  --audio "<audio-path>" \
  --timeline "<timeline.json>" \
  --transcript "<transcript.json>" \
  --project-name "<project name>" \
  --output "<project-folder>"
```

`project-name` 只用于浏览器标签和 README，不得渲染到 `1920 × 1080` 录制舞台。

脚本会创建：

- `standalone-preview.html`
- 嵌入的音频 Data URI
- `timeline.json`
- `transcript.raw.json`
- `START_WINDOWS.bat`
- `START_MAC_LINUX.sh`
- `README.md`

生成的页面是可运行脚手架。根据实际内容替换通用 cue 渲染器，同时保留播放控制、音频同步、URL 参数和录制模式。

### 9. 播放契约

页面必须支持：

- 普通预览模式，控制面板位于 `1920 × 1080` 舞台之外。
- `?record=1`：隐藏控制面板和裁切参考线，只保留旁白驱动内容。
- `?autoplay=1`：自动开始播放。
- `?delay=3`：延迟播放，为 OBS 启动录制预留时间。
- `?guide=1`：显示竖屏裁切参考线。
- `?t=30`：检查正文开始后第 30 秒。
- 空格键：播放或暂停。
- 左右方向键：前后跳转 5 秒。
- `R`：重置。

最终独立 HTML 必须嵌入音频，或保证能从交付文件夹中的本地路径稳定加载。不能留下没有提示的静音播放失败。

### 10. OBS 录制契约

推荐使用 OBS Browser Source：

- URL：`http://127.0.0.1:8000/standalone-preview.html?record=1&autoplay=1&delay=3`
- 宽度：`1920`
- 高度：`1080`
- 帧率：`30` 或 `60`

不要建议录制 Chrome 地址栏。如果临时使用 Chrome，`F11` 只能作为备用方式。

### 11. 交付前验证

运行：

```bash
python scripts/validate_delivery.py "<project-folder>"
```

必须检查：

- JSON 可以正常解析。
- 时间轴总时长有效。
- cue 时间位于场景边界内。
- HTML 已嵌入音频。
- HTML 支持 `record`、`autoplay`、`delay` 等参数。
- 画布为 `1920 × 1080`。
- 不存在缺失的 CDN 或本地资源依赖。
- 除非用户明确要求，录制舞台中不能出现课程包装或播放进度信息。
- 时间轴中不存在旧的全局 `title`、场景 `title`、`eyebrow` 或 `summary` 字段；没有当前 cue 时录制舞台保持空白。
- 抽查每个场景的代表 cue：只显示当前 beat，旧 beat 已退场。
- 启动脚本存在。
- ZIP 包含完整项目。

## 交付内容

始终提供以下链接：

1. 独立动画预览。
2. 完整 ZIP。
3. 转写 JSON。
4. 时间轴 JSON。
5. 生成清洗稿时，同时提供清洗稿。

明确说明所有限制，例如：无法直接使用 ASR、基于锚点完成对齐、术语尚未验证，或场景时间仍需人工复核。
